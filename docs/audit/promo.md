### P-06 — עקיפת reCAPTCHA עם `'dev-bypass'` (לא אומת)
- **חומרה:** בינוני
- **קבצים:** `index.html:1551`, `demo.html:135-147`, `hadmayot.html:255-266`, `hadmayot-thanks.html:309-319`
- **ראיה:** `const done = (t) => res(t || 'dev-bypass');`, ובכל כשל נשלח `recaptchaToken: 'dev-bypass'`.
- **השפעה:** אם השרת מקבל `dev-bypass` כטוקן תקף בייצור, ה-reCAPTCHA לא שווה כלום ובוט יכול לשלוח את המחרוזת ישירות. בפועל נשארים רק honeypot ו-rate-limit. **לא אומת**, כי קוד השרת לא בריפו הזה.
- **תיקון מוצע:** לוודא שבשרת `dev-bypass` מתקבל רק בסביבת פיתוח. בייצור אפשר לקבל אותו רק עם ציון סיכון מחמיר יותר או אימות נוסף, ולא להכניס ליד כזה לדיוור אוטומטית.

### P-07 — אין כותרות אבטחה (`_headers`)
- **חומרה:** בינוני
- **קובץ:** אין `_headers` בשורש הריפו.
- **ראיה:** `git ls-files` לא מחזיר `_headers` ולא `_redirects`.
- **השפעה:** אין `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors` (אפשר להטמיע את עמוד הרכישה במסגרת), `X-Content-Type-Options`, `Referrer-Policy` או `Permissions-Policy`. בלי `Referrer-Policy`, כתובת עם `?e=<מייל>` עלולה לדלוף ב-Referer ל-YouTube, ל-CDN או ל-Cloudflare (לא אומת).
- **תיקון מוצע:** להוסיף `_headers`, למשל:
  ```
  /*
    X-Frame-Options: DENY
    X-Content-Type-Options: nosniff
    Referrer-Policy: strict-origin-when-cross-origin
    Permissions-Policy: camera=(), microphone=(), geolocation=()
  ```
  ובשלב שני CSP שמותר בה רק המקורות הקיימים (jsdelivr, unpkg, google.com/recaptcha, cloudflareinsights, fonts, youtube, `office.daitsh.com`, `tacles.vercel.app`).

### P-08 — סקריפטי צד שלישי בלי גרסה קבועה ובלי SRI
- **חומרה:** בינוני
- **קבצים:** `https://unpkg.com/lucide@latest` נטען ב-8 עמודים (למשל `hadmayot.html:11`, `demo.html:11`). `https://cdn.tailwindcss.com` נטען ב-9 עמודים (למשל `index.html:18`).
- **ראיה:** אין `integrity=` באף קובץ HTML.
- **השפעה:** שינוי או פריצה בגרסה האחרונה של lucide משנים מיד את האתר החי, כולל עמוד הרכישה. Tailwind Play CDN לא מיועד לייצור: הוא מקמפל CSS בזמן ריצה, מאט את הטעינה ומדפיס אזהרה בקונסול.
- **תיקון מוצע:** לקבע גרסה (`lucide@0.469.0`, כמו שכבר נעשה בעמוד אחד) ולהוסיף `integrity` ו-`crossorigin`. לבנות CSS סטטי של Tailwind בבנייה מקומית.

### P-09 — "שער" המדריך והפרומפטים עובד רק בצד הלקוח
- **חומרה:** בינוני
- **קבצים:** `hadmayot-thanks.html:20-22`, `hadmayot-prompts.html:13`, `hadmayot-guide.html:8,21`
- **ראיה:** `if (/^[^\s@{}<>]+@[^\s@{}<>]+\.[^\s@{}<>]+$/.test(e)) { ok = true; ...` וגם `localStorage.setItem('hadmayot_ok', '1')`.
- **השפעה:** כל כתובת בצורת מייל (`?e=a@b.c`) או ערך ב-localStorage פותחים את התוכן. כל התוכן נמצא בקוד ה-HTML, ו-`view-source` או סורק רואים אותו. `hadmayot-guide.html` ו-`hadmayot-prompts.html` גם לא מסומנים `noindex`. בפועל איסוף הלידים לא נאכף.
- **תיקון מוצע:** אם זה מכוון ("שער רך"), לתעד את זה ולהוסיף `noindex`. אם רוצים אכיפה אמיתית, להגיש את התוכן מ-Worker/Function שבודק טוקן חתום שנשלח במייל.

## 4. איכות, SEO, ביצועים

**קישורים ותמונות פנימיים:** סקריפט בדיקה עבר על כל `src` ו-`href` המקומיים ב-12 קבצי ה-HTML וב-`shared.js`. **לא נמצא אף קישור שבור.** בכל `<img>` יש `alt`. בכל העמודים יש `lang`, `dir="rtl"` ו-`viewport`.

### P-14 — SEO חסר
- **חומרה:** בינוני
- **ראיה:**
  - אין `sitemap.xml` ואין `robots.txt`.
  - אין `rel="canonical"` באף עמוד.
  - `og:*` מוגדר רק ב-`index.html`, ושם `og:image` יחסי: `index.html:12` `<meta property="og:image" content="1.jpg">`.
  - חסר `description` ב-`hadmayot-prompts.html` ובמודעה.

- **תיקון מוצע:** להוסיף `sitemap.xml` ו-`robots.txt` (עם `Disallow` לעמודי התודה), `canonical` מוחלט בכל עמוד, ו-`og:image` מוחלט (1200×630). להחליט על דומיין ראשי ולהפנות אליו את `pages.dev` ב-`_redirects` או בהגדרות Cloudflare.

## מה נבדק ונמצא תקין
- אין מפתחות פרטיים או סודות בקוד. מפתח האתר של reCAPTCHA (`6LcXzhMt...`) וה-token של Cloudflare Web Analytics הם ציבוריים מעצם הגדרתם.
- אין קבצי `.env`, דאמפים או גיבויי מסד נתונים.
- `innerHTML` משמש רק עם תוכן סטטי מהקוד. ערכי `?e=`/`?n=` נבדקים מול regex ומוזנים ל-`.value`, ולא ל-HTML. לא נמצא XSS.
- `mailto-gmail.js` מאפס `w.opener = null`.
- עמודי התודה מסומנים `noindex`.
- צבעי המותג נכונים ואין כחול.
